# AI CV Manager — скиллы Codex для поиска работы

Четыре самостоятельных скилла для Codex Desktop и CLI: анализ резюме,
создание и редактирование, автоматические отклики и строгое мок-собеседование.
Площадки первой версии: **hh.ru, hh.kz, enbek.kz**.
Языки: **русский (`ru`), қазақша (`kk`), English (`en`)** — только выбранные
пользователем. Набор универсальный: личные данные и предпочтения автора
не включены в рабочие настройки.

| Скилл | Когда использовать |
| --- | --- |
| [resume-review](skills/resume-review/SKILL.md) | Оценка резюме и конкретные рекомендации под роль или вакансию |
| [resume-edit](skills/resume-edit/SKILL.md) | Новое резюме, правки на сайте, версии и экспорт PDF/DOCX/MD |
| [job-apply](skills/job-apply/SKILL.md) | Поиск по согласованным фильтрам, отклики, короткие письма, MD-журнал |
| [mock-interview](skills/mock-interview/SKILL.md) | По одному вопросу без подсказок, оценка только в конце |

Это набор инструкций и локальный помощник журналирования, а не отдельный
сервис рассылки. Браузерные инструменты подключаются в вашей установке Codex.
Скиллы не предоставляют аккаунты, доступ к браузеру и фоновый запуск сами
по себе. Для работы не требуется отдельный API-ключ OpenAI.

## Быстрый старт в этом проекте

1. Откройте папку проекта в Codex Desktop или запустите `codex` из этой папки.
2. Для автоматического обнаружения скопируйте нужные скиллы в локальную
   `.agents/skills/`. Команды ниже предназначены для первой установки,
   когда одноимённых папок назначения ещё нет:

   ```sh
   mkdir -p .agents/skills
   cp -R skills/resume-review skills/resume-edit skills/job-apply skills/mock-interview .agents/skills/
   ```

3. Начните новый чат. Если навыки не появились, перезапустите Codex.
4. Прикрепите резюме либо укажите площадку и резюме в своём аккаунте.
5. Назовите выбранные языки и нужный сценарий. Для работы на сайте
   подключите браузер по инструкции ниже.

До установки можно явно попросить Codex прочитать, например,
`skills/resume-review/SKILL.md` и выполнить запрос по нему.
Корневой [AGENTS.md](AGENTS.md) также указывает пути к исходникам.
Создание файлов этого набора не меняет глобальные настройки Codex.

Примеры запросов внутри чата Codex (это не команды оболочки):

```text
Используй $resume-review. Язык русский. Оцени прикреплённое резюме
под должность аналитика и предложи конкретные улучшения.

Используй $resume-edit. Қазақ тілінде жұмыс істейік.
Түйіндемемді жақсартып, PDF және DOCX нұсқаларын дайында.
Сайтқа сақтамас бұрын өзгерістерді көрсет.

Use $mock-interview in English for the vacancy I attached.
Ask one question at a time and provide feedback only at the end.

Используй $job-apply на hh.kz, резюме «Бизнес-аналитик».
Работаем только на русском. Посмотри доступные фильтры, затем спроси
их значения. Нужно 15 откликов с короткими письмами.
```

## Установка в другой проект и публикация

Для другого проекта создайте в нём `.agents/skills/` и скопируйте туда
нужные папки из `skills/`. Можно использовать любой один скилл:
его инструкции, справочные материалы и необходимые помощники находятся
внутри собственной папки. Копировать `shared/` при установке не нужно.

Для персональной установки можно разместить нужные папки в
`~/.agents/skills/`. Команды в этом README ничего не устанавливают туда
автоматически. При обновлении заменяйте папку конкретного скилла целиком,
сохранив персональные журналы в рабочем проекте.
Размещение `.agents/skills` соответствует [документации Codex](https://learn.chatgpt.com/docs/build-skills).

Для распространения публикуйте исходники из `skills/`, README, общие
источники `shared/` и инструменты проверки. Пример настройки поиска
в `assets/` иллюстративный: его значения не являются пользовательскими.
Не включайте свои резюме, cookies, журналы и отчёты. Эти рабочие каталоги
перечислены в `.gitignore`; сам `.gitignore` не удаляет уже опубликованные файлы.
Лицензию распространения автор выбирает отдельно; этот набор её не назначает.

## Подключение браузера

### Codex Desktop

Сначала используйте браузер с установленным расширением и действующей
сессией. В версиях Desktop с поддержкой управления браузером подключите
нужный профиль через настройки браузерных инструментов. В текущей официальной
документации описаны Settings → Computer Use и выбор браузера через `@`;
названия и доступность зависят от версии/настроек установки.
Смотрите [официальное руководство расширения](https://learn.chatgpt.com/docs/chrome-extension).

Проверьте, что агент действительно видит нужную вкладку и аккаунт.
Открытая вкладка рядом с чатом сама по себе не доказывает доступ к её управлению.
Если собственный мост Desktop недоступен, можно настроить браузерный MCP.

### Codex CLI: Playwright MCP с расширением

CLI нужен отдельно подключённый браузерный инструмент. Один вариант —
официальный Playwright MCP с Playwright Extension в Chrome/Edge.
Установите Node.js и расширение по [руководству Playwright](https://playwright.dev/mcp/configuration/browser-extension).
В настройках MCP Codex добавьте сервер с командой `npx`
и аргументами `@playwright/mcp@latest`, `--extension`.

Пример секции `config.toml` для ручной настройки MCP:

```toml
[mcp_servers.playwright]
command = "npx"
args = ["@playwright/mcp@latest", "--extension"]
```

Это пример для добавления к существующей конфигурации, не замена всего
файла. Сначала проверьте установленную версию и её способ настройки MCP.
Подключение расширения может потребовать подтверждения пользователя.
Режим `--extension` использует уже открытый профиль и авторизованные вкладки.
При нескольких профилях выберите нужный, не разрешая доступ к посторонним.

Если подключиться не получилось, агент предлагает импорт сессии средствами
доступного инструмента либо самостоятельный вход во встроенном браузере
Desktop/отдельном управляемом браузере CLI. Поддержка импорта проверяется,
а не предполагается. Cookies не нужно вставлять в чат; их нельзя хранить
в публичном репозитории. Пароли, MFA, CAPTCHA и ЭЦП пользователь вводит сам.

## Правила работы

### Резюме и ATS

Источник — прикреплённый файл или выбранное резюме на сайте. Если данных нет,
агент запрашивает их. Редактор готовит сильные формулировки, акцентирует вклад
и результат. Можно обсуждать новые оценки метрик, стаж, названия должностей
и другие факты; каждое существенное изменение показывается отдельно.
Новые числа и изменённые факты должны быть конкретно подтверждены
пользователем перед финальным экспортом, публикацией или отправкой.
Гипотезы не выдаются за проверенные сведения.

Правки на сайте сначала показываются пользователю; явная команда
«сохраняй без подтверждения» разрешает редакторские изменения без повторного
вопроса. Она не подтверждает ещё неизвестные новые цифры и факты.
Анализ резюме сам по себе не разрешает публикацию.

ATS-рекомендации ориентированы на читаемость, извлечение текста,
релевантные навыки и правильное заполнение полей. Собственный балл анализа
не является рейтингом площадки и не предсказывает процент приглашений.
Скрытые ключевые слова и инструкции для оценочного ИИ не используются.
Основа рекомендаций: [описание парсинга Greenhouse](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse)
и [пояснения HeadHunter о навыках](https://feedback.hh.ru/knowledge-base/article/5453).
Источники проверены **21 октября 2026 года**; скиллы предусматривают их обновление.

PDF/DOCX создаются штатным экспортом площадки или доступными инструментами
документов. При отсутствии инструментов агент называет ограничение и отдаёт
готовый текст, не выдавая его за PDF. Предусмотрены история версий,
проверка извлечённого текста, вёрстки и казахских символов.

### Поиск и отклики

Перед серией агент изучает доступные фильтры площадки, затем запрашивает
выбранные значения и количество откликов. «Все» допускается, но любая серия
ограничена **одним часом с начала задачи**, включая подготовку и ожидание.
Если подготовка заняла час, требуется новая команда для нового запуска.
Самовольное расширение фильтров или выбор другого резюме запрещены.

Каждая карточка открывается в отдельной вкладке и читается полностью.
После отклика агент фиксирует результат, закрывает свою временную вкладку
и возвращается в поиск. Письмо короткое, деловое, по конкретной вакансии
и выбранной версии резюме. Команда на серию разрешает отправку подходящих
откликов без подтверждения каждого письма.

Если площадка не позволяет приложить письмо, это согласуется до серии;
подготовленный текст сохраняется в журнале как неотправленный.
Возможности Enbek проверяются по текущему интерфейсу и
[официальной помощи](https://www.enbek.kz/ru/faq).
Внешние анкеты и неизвестные обязательные сведения пропускаются с причиной.

Серия заканчивается по первому условию: час, количество, конец выдачи,
команда остановки либо препятствие работе. При неясном исходе после клика
повторная отправка блокируется до проверки истории.
Тот же ID резюме не откликается на ту же вакансию повторно; переименование
резюме этого не меняет. Другое резюме рассматривается отдельно.

### Журнал

Формат: `logs/<ресурс>__<название-резюме>-<короткий-id>.md`.
Внутри: время с часовым поясом, вакансия, компания, URL, резюме, статус,
причина/подтверждение и полный текст письма. Короткий ID предотвращает
смешивание одинаковых названий у разных резюме/аккаунтов.
Состояние серии хранится в `private/runs/`.

В [инструкции журнала](skills/job-apply/references/journal.md) описан
помощник `application_log.py`: подготовка до отправки, лимит, дедлайн,
устойчивые ID, статусы и восстановление после обрыва. Для него нужен Python
3.10+; на ОС без базы часовых поясов дополнительно нужен `tzdata`.
Он не управляет браузером и не проверяет истинность внесённого подтверждения.
Для повторных запусков используйте ту же рабочую папку с прежними журналами;
проверка истории сайта обязательна в любом случае.

Часовой предел запрещает новые действия после срока, а скрипт блокирует новую
подготовку отправки. Уже запущенный внешний инструмент нельзя гарантированно
прервать одним текстом скилла: для строгого прерывания нужен таймаут среды.
Набор не запускает фоновую рассылку и не обещает работу после закрытия чата.

### Собеседование и тематика чата

Мок-собеседование заканчивается после **15 основных вопросов или 30 минут**.
Вопросы по одному, не более двух нейтральных уточнений на основной вопрос.
До конца нет подсказок, баллов и похвалы. Итог — полный разбор ответов,
ошибок, уровня, противоречий и план подготовки. Время ожидания входит в лимит;
при отсутствии механизма пробуждения дедлайн проверяется на следующем ходе.

Скиллы сохраняют карьерную тематику активного сценария. Для постоянного
ограничения отдельного рабочего проекта используйте также [AGENTS.md](AGENTS.md).
Не копируйте это ограничение в общий проект разработки без намерения сделать
его карьерным ассистентом. Разработка самих скиллов допускается по прямому запросу.

## Сопровождение и проверка

Общие инструкции редактируются в `shared/`, затем копируются в скиллы:

```sh
python3 scripts/sync_references.py
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
```

Синхронизация нужна только сопровождающему набора. Установленные скиллы
не зависят от `shared/`. После изменения исходников обновите и установленные
копии в `.agents/skills/`, если используете их.
Валидатор проверяет манифесты, локальные ссылки, UI-метаданные, синтаксис
помощников и согласованность общих материалов. Тесты проверяют реальные
инварианты журнала и не заходят в аккаунты.
[Поведенческие сценарии](tests/behavioral-scenarios.md) предназначены для
проверки на фиктивных данных. Наличие локальных тестов не означает, что
текущий интерфейс живых площадок уже проверен автоматически.
