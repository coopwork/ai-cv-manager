# MD-журнал и локальные ограничения

Используй `scripts/application_log.py` относительно директории этого скилла.
Требуется Python 3.10+ и стандартная библиотека; для IANA-зон на некоторых ОС
может понадобиться пакет `tzdata`. Скрипт не подключается к сайтам.

## Файлы и идентичность

Рабочая папка — текущий проект пользователя, а не папка установленного скилла.
Все команды принимают `--workspace /абсолютный/путь/к/рабочей/папке`
перед подкомандой. Используй абсолютный путь к самому скрипту.
Ниже команды показаны при установке исходников в `skills/`.

Журнал: `logs/<сайт>__<название-резюме>-<короткий-id>.md`.
Суффикс устраняет совпадения одинаковых названий у разных резюме/аккаунтов.
Состояние серии: `private/runs/<run-id>.json`.
Переименование резюме не снимает повторы: при проверке сканируются все
MD-журналы рабочей папки по семейству площадки, аккаунту, стабильному ID
резюме и вакансии. Для hh.ru/hh.kz одинаковые ID вакансий объединяются.
Используй один и тот же локальный псевдоним аккаунта между сериями,
не адрес почты/телефон; не объединяй разные аккаунты без проверки.
Новая рабочая папка без прежних журналов не знает локальную историю;
историю сайта проверяй в любом случае.

MD содержит человекочитаемые записи и комментарии `cv-event` для машинной
проверки. Не удаляй и не редактируй комментарии вручную. Повреждённая запись
блокирует отправки до восстановления. Журнал и файлы `private/` приватны.

## Начало

Подготовь JSON по `assets/run-config.example.json`, заменив пример реальными
согласованными значениями. `max_applications=null` означает «все до часа».
Значения в примере не являются настройками пользователя.
`started-at` — сохранённое начало всей задачи, не время завершения подготовки.

```sh
python3 skills/job-apply/scripts/application_log.py start --config private/run-config.json --started-at '2026-10-21T09:00:00+05:00'
```

Дата в команде — только иллюстрация синтаксиса, подставь настоящее начало.
Сохрани возвращённый `run_id`. Новый запуск для того же резюме запрещён,
пока предыдущая серия активна; продолжение использует её ID и дедлайн.

## Проверка и подготовка перед отправкой

```sh
python3 skills/job-apply/scripts/application_log.py check --run RUN_ID --url 'https://hh.kz/vacancy/123456'
python3 skills/job-apply/scripts/application_log.py status --run RUN_ID
```

`check` возвращает `eligible` и причину; код выхода 2 означает запрет,
1 — ошибку, 0 — разрешение. Разрешение не доказывает соответствие вакансии
или отсутствие отклика в истории сайта.

Создай приватный JSON текущей карточки с полями:

```json
{
  "url": "https://hh.kz/vacancy/123456",
  "vacancy_title": "Фактическое название вакансии",
  "company": "Фактическое название компании",
  "cover_language": "ru",
  "cover_status": "included",
  "cover_letter": "Полный фактически отправляемый текст письма."
}
```

```sh
python3 skills/job-apply/scripts/application_log.py record --run RUN_ID --status prepared --data private/current-application.json
```

Сохрани возвращённый `application_id`. Только после успешной записи
проверь остаток времени ещё раз и нажимай фактическую отправку.
`prepared` резервирует место в квоте и блокирует повтор при обрыве.
Если форма изменила текст, до отправки заверши прежнюю подготовку как
`failed` с свидетельством отсутствия отправки и подготовь точный текст заново.

Если письма нет в интерфейсе, используй `cover_status=unavailable`
только при `allow_without_cover=true`; текст всё равно сохрани локально.
Это не означает отправку письма работодателю.

## Результат

Добавь к JSON `evidence`: наблюдаемое сообщение/статус сайта без секретов.

```sh
python3 skills/job-apply/scripts/application_log.py record --run RUN_ID --status submitted --data private/current-application.json --application-id APPLICATION_ID
```

Вместо `submitted` используй `unknown` при неясном исходе. Оба требуют
предыдущего `prepared` и наблюдаемого основания. `unknown` можно разрешить
в `submitted`, `already_applied` или подтверждённый `failed` с тем же ID.
Скрипт доверяет внесённому свидетельству; сам он не видит сайт.
После дедлайна он разрешает записать исход уже подготовленной операции,
но не новую подготовку/отправку.

`already_applied` без `prepared` используй при обнаружении прежнего отклика
на сайте именно с выбранным резюме, сохранив `evidence`.
`skipped`/`failed` требуют `reason`; `failed` для существующей операции также
требует подтверждения, что отправки не было. При пропуске без клика
не передавай ID другой операции.

Записи `submitted`, `already_applied`, `prepared`, `unknown` блокируют
повторную отправку с тем же резюме. `failed`/`skipped` сами по себе не блокируют.
`prepared`/`unknown`/`submitted` текущей серии учитываются в квоте N;
подтверждённый прежний отклик `already_applied` квоту не расходует.

## Остановка

```sh
python3 skills/job-apply/scripts/application_log.py finish --run RUN_ID --reason one_hour_deadline
```

Другие причины: `application_limit`, `results_exhausted`, `user_stop`,
`authentication_required`, `rate_limited`, `journal_error`.
Перед итогом возьми `status` и назови причину завершения из состояния серии.
Операции сериализуются локальной блокировкой. Если осталась блокировка
после аварии, сначала убедись, что другого процесса нет; не удаляй её вслепую.
Скрипт не обеспечивает распределённую блокировку между разными устройствами
или рабочими папками и не заменяет проверку истории площадки.
